# 公式申込の自動入力（独立機能）

トップの「申し込みはこちら」の下にある「自動申し込み」から `/auto-input` に移動します。
メール・住所・品目・希望曜日の設定、端末への任意保存、公式メール認証後の転記、公式画面の確認・修正に対応します。
処分リストの未搬出品目を初期候補にします。同名の品目は数量を合算します。前のページの最新リストを保存済み申込品目より優先します。リストを空にした場合も反映します。
収集予定の日付・排出場所も引き継ぎます。指定日の空きがない場合は停止します。自由記入の排出場所は確認用に表示し、公式の選択肢に完全一致する場合だけ選択欄にも反映します。
公式品目名は完全一致が必要です。候補を確認・修正してください。合計6点までです。

## 通常の開発

`jphacks2026` でこれまでどおり `npm run dev` / `npm run build` が使えます。
自動入力ページは遅延読み込みで、CSSはページ内に限定しています。
Playwrightはこのディレクトリだけの依存で、通常のアプリのインストールや起動には不要です。
通常起動では入力設定画面を利用できますが、公式への自動入力には以下の専用サーバーが必要です。

## 初回準備

`jphacks2026` で実行します。

```sh
npm ci --prefix official-auto-input
cd official-auto-input
npx playwright install chromium
cd ..
```

## アプリと自動入力をまとめて起動（ビルド版）

```sh
npm run auto-input
```

http://127.0.0.1:3001/ を開きます。自動入力ページは http://127.0.0.1:3001/auto-input です。
コードを変更した場合は停止して再実行します。

## 画面を編集しながら自動入力を使う

2つのターミナルを `jphacks2026` で開きます。

```sh
# ターミナル1：自動入力API
npm --prefix official-auto-input start
```

```sh
# ターミナル2：通常のdevサーバーを停止してから実行
npm run dev:auto-input
```

http://127.0.0.1:5173/ を開きます。専用のVite設定だけがAPIを3001番へ中継します。
通常の `vite.config.ts` は変更していません。APIはこのMacのループバックアドレスだけで待ち受けます。
3001番と5173番のブラウザー保存領域は別です。

## 操作

1. メール・住所・品目・希望曜日を入力します。端末への保存は任意です。
2. 「設定した内容で開始」で公式専用ブラウザーを開きます。メール欄へ入力するだけで、送信はまだしません。
3. 公式の注意事項を確認し、本人が確認メールを送信します。
4. 届いたメール本文の元のリンクを貼り付けて認証します。認証URLは保存しません。
5. 住所が転記されたら公式画面の画像で地図を確認し、「地図の住所を確認して品目入力へ進む」を押します。
6. 品目と希望日を確認し、最終申込・支払いは本人が操作します。自動処理で最終申込や支払いは行いません。
7. 終了時に専用ブラウザーを終了します。30分操作しない場合も終了します。

公式画面は変更される場合があります。転記に失敗した場合は途中まで入力されていることがあるため、画面を更新して確認してください。
希望曜日に空きがない場合は停止します。別の曜日に変更しません。

## 検証

```sh
npm run build
node --test official-auto-input/validation.test.mjs
node --check official-auto-input/server.mjs
```

ローカルで画面遷移、品目引継ぎ、設定保存・削除、スマホ幅、API接続、別サイトからの操作拒否を確認しています。
認証後の実データ転記・最終申込・決済は実行していません。

## Gmailから確認メールを自動取得する（初回設定が必要）

1. Google Cloudでプロジェクトを用意し、Gmail APIを有効にします。
2. Google Auth Platformの同意画面を設定し、テスト中は利用するGoogleアカウントをテストユーザーに追加します。
3. OAuthクライアントを「ウェブアプリケーション」で作成し、承認済みリダイレクトURIに `http://127.0.0.1:5173/api/automation/gmail/callback` を登録します。
4. このフォルダの `.env.example` を `.env` にコピーし、クライアントID・シークレットを記入します。`.env` はGit対象外です。値はチャットに貼らないでください。
5. `npm --prefix official-auto-input start` で専用サーバーを再起動し、`http://127.0.0.1:5173/` から利用します。
6. 公式専用ブラウザーを開始し、申込メールアドレスを入力した後、「Gmailを接続して自動取得」を押して同じGoogleアカウントで許可します。
7. 公式画面から本人が確認メールを送信すると、最大2分間・5秒間隔で受信を確認します。取得したリンクを欄に反映した後、本人が認証ボタンを押します。時間切れの場合は再取得できます。

Gmailの `gmail.readonly` 権限を使います。権限自体はメールボックスの読み取りを許可しますが、この機能は申込開始後に届いた那覇市公式ドメインからのメールだけを検索します。メールの既読化・送信・削除は行いません。公式メールの差出人ドメインや形式が変わると取得できない場合があります。
アクセストークンはサーバーのセッションメモリだけに保持し、ファイルやブラウザーには保存しません。セッション終了・サーバー再起動・接続期限切れ後は再接続が必要です。

スマホ実機でGoogle接続を使うには、スマホから到達できるHTTPSのアプリURLと、そのURLに対応するGoogleのリダイレクト設定が必要です。LANのHTTP IPアドレスはこのGoogle接続の設定例には使えません。現状の初期設定例はこのMac向けです。
公開運用前にはGoogleのOAuth公開・検証要件も確認してください。

公式資料：
- https://developers.google.com/identity/protocols/oauth2/web-server
- https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list

実アカウントの接続には上記設定と本人の同意が必要です。接続情報未設定の環境では、リンク抽出・OAuth不正state拒否・画面動作をテストし、実際のGmail取得は未検証です。
