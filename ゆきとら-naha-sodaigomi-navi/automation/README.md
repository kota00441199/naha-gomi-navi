# 公式受付の自動入力（試験版）

`npm start` はアプリと専用ブラウザーのAPIを3000番で起動します。初回は `npx playwright install chromium`、画面を変更した場合は `npm run build` が必要です。従来の静的配信は `npm run start:static`。3001番の静的配信では自動入力は利用できません。

## 操作

1. アプリの「公式申込の自動入力」を開き、専用ブラウザーを開始。
2. 公式画面の入力欄でメールアドレスを入力。同意内容を本人が確認し、メール送信。
3. 受信メール本文にある元のリンクをコピーし、専用ブラウザーで開く欄に貼る。別ブラウザーで移動した後のprofile URLでは認証できない。
4. 住所・連絡先を記入し、公式サイトへの入力チェック後「住所・連絡先を自動入力」。公式画面で内容と地図を確認し、本人が品目選択へ進む。
5. 公式品目名（大小などを含む）と数量を確認し「品目・数量を自動入力」。名称は完全一致のみ。既存のチェックがある場合は停止。
6. 自動操作は転記まで。以降は本人が公式画面を確認。外部決済サイトへの遷移には未対応。

## 個人情報と接続

住所は画面内メモリーのみで扱う。入力した個人情報、認証URL、ブラウザーの保存状態をファイルへ保存しない。独立したブラウザーセッションをHttpOnly/SameSite Cookieに結び付け、他のセッションと共有しない。30分の無操作で破棄。「終了して入力情報を消去」でブラウザーも閉じる。サーバー再起動時は全セッションを失う。アプリ再読み込み後は「専用ブラウザーを開始」で既存の有効な接続を再取得する。ブラウザーのフォーム履歴等は利用者側の設定に依存する。

現在は同じWi-Fi内での試験利用向け。HTTP通信をインターネットへ公開しない。運用公開にはHTTPS、利用者認証、負荷制限と実機検証が別途必要。APP_HOSTSで許可するPCのホスト/IPを設定できる。現在の既定値はlocalhost,127.0.0.1,10.10.7.62。アクセスログへ入力内容を出力しない。

## 検証範囲

入力検証テストは `npm run test:automation`。URL制限、数量・重複、住所必須項目のチェック。公式フォームの自動転記は観測した現行画面の構成に基づく実装。認証後の実サイトでの一連の転記は、メール認証済みセッションで受入確認が必要。画面の項目数や名前が変わると停止する。部分入力に失敗した場合は画面を更新し確認する。

## 設定保存・希望曜日・連続入力

初回設定でメール・住所・品目・希望曜日を入力し、「この端末に保存する」を選んで保存するとlocalStorageに保持します。共有端末では使用しないか、使用後に保存設定を削除してください。認証URLは保存しません。設定保存は任意で、サーバーには個人情報ファイルを作りません。

「設定した内容で開始」は公式のメール入力欄まで転記します。メール送信・同意は本人が公式操作欄で実行します。元の認証リンクを貼り、「認証して住所・品目・日付を自動入力」を押すと、申込者情報→自宅確認→品目検索と完全一致選択→空き日の選択まで連続操作します。日付は日本時間を基準に、選んだ曜日内で最短の空きを選びます。条件に合わない場合は停止します。最終申込・決済は自動操作しません。住所と品目とカレンダーの連続実サイト検証は認証リンク待ちです。
