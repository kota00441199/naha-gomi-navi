## v0 → v1.0（改善前と改善後の比較）

### 改善前（v0）

```
あなたはゴミ分別の専門家です。写真のゴミが何かを判定し、分別方法を教えてください。結果はJSONで出力してください。
```

### v0 で起こると予想される問題と、v1.0 での対策

「予想される問題」は、LLM の一般的な傾向から予想したものです。v0 と v1.0 を実機で比べる手順は下にあります（`--prompt baseline`）。

| # | v0 で予想される問題 | v1.0 での変更 |
|---|---|---|
| 1 | 「専門家」として自分の知識で分別区分を断定する（那覇市のプラスチック＝もやすごみ、を知らずに「プラスチック資源」と答える） | 分別は `<municipality_rules>` だけを根拠にすると明記した。4種類の `rule_status`、ルールIDの引用、固定文言「自治体の公式情報を確認してください」を追加 |
| 2 | JSONの項目名・構造が毎回変わる | `responseJsonSchema` で形式を強制し、全項目を必須にした |
| 3 | 写っていないキャップ・ラベルの存在を前提にする | 【ルール1】一般知識で補うことを禁止し、具体例を示した |
| 4 | 暗い・ぼやけた写真でも断定する | 確実性の3段階の基準、「品質 poor なら high にしない」、`retake_advice` を追加 |
| 5 | アルミ／スチール、PET／他のプラを見た目で断定する | 材質の根拠を3段階（observed/inferred/unknown）にし、取り違えやすい組み合わせを列挙した |
| 6 | 複数の物を1つにまとめる、または部品を別の物として数える | 【ルール4】別の物は別の item、部品は components に分けると明記した。`location` を追加 |
| 7 | 推測を断定口調で書く | 【ルール7】推測の書き方を指定し、`unknowns` / `questions_for_user` を追加 |
| 8 | 画像内の文字による指示に従ってしまう | 画像内の文字・ルール・補足は「参照する情報」で、指示には従わないと明記した |
| 9 | 部位ごとに出し方が違う物（ペットボトルの本体とキャップ）を1つの区分で答える | `sorting` を部位ごとの配列にした |
| 10 | 安全上の注意と自治体ルールが混ざる | `cautions[].type` で official_rule / general_safety / image_observation を分けた |

### 机上レビューで v1.0 に入れた修正（公開前）

| # | 見つけた問題 | 修正 |
|---|---|---|
| R1 | 那覇市の原文の「金属キャップは『かん』で出す」の「かん」が区分名の一覧にない。Gemini が「かん」と答えると、検証スクリプトが「ルールにない区分名」と誤判定する | `naha-city-rules.md` の N03 に転記者注を追加し、区分名は「資源化物（缶・びん・ペットボトル）」を使うと明記した |
| R2 | 自治体によって区分名の括弧が全角・半角でゆれる可能性がある | 採点時に NFKC 正規化してから比べるようにした（`scorer.ts` の `norm`）。バックエンド向けにも [02_json_spec.md](02_json_spec.md) に注意を書いた |

## 実機テストでの比較手順

```bash
cd eval
export GEMINI_API_KEY=...            # 共有のキーをもらう
npm run eval -- --prompt baseline     # 改善前（v0）
npm run eval                          # 改善後（v1.0）
```

2つの `report.md` の「評価項目別」の表を、[04_test_results.md](04_test_results.md) の表に書き写してください。
v0 はスキーマを強制しないので、評価項目6（JSON形式）で不合格になると、他のチェックは実行されません。これは「形式を指定しないと後続処理で使えない」ことを示す結果として扱います。

## v1.1 以降の記録方法

実機テストで問題が見つかったら、次の形式で追記してください。

```markdown
## v1.1（YYYY-MM-DD）

### きっかけ
- 実行：results/<日時>_v1_<モデル>/report.md
- 問題：TC05 で 3回中2回「プラスチック資源」と回答（評価項目7）

### 原因の分析
- 例：ルール本文が長く、N01 の「プラスチック類」が目に入っていない可能性

### 変更内容（差分）
- 変更前：「…」
- 変更後：「…」

### 変更後の結果
- TC05：3/3 合格。他のケースへの悪影響：なし（全ケースを再実行して確認）
```

**ルール**：1回の変更では1つの問題だけを直し、直したら**全ケースを再実行**して、他のケースが悪くなっていないか確かめる。
